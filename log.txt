You are an expert Python architect and crawling pipeline designer.

I am building a YouTube crawling system with the following workflow:

1. Input a keyword (e.g., "아이유 직캠")
2. Perform YouTube search and extract a large pool of candidate video URLs
    - At least 30–50 URLs per keyword
    - Avoid API calls that require authentication unless absolutely necessary
3. Filter candidate videos by metadata:
    - view_count ≥ 100
    - comment_count ≥ 5
    - (You may add additional filters if helpful)
4. Distribute the final filtered URLs across multiple worker processes
    - Use Python multiprocessing (not threading)
    - Each worker launches its own Playwright instance
    - Each worker runs an async crawler: extract full comments + replies
5. Aggregate the results and return:
    - total_videos_processed
    - total_comments_collected
    - failed_urls list
    - per_video stats

Your task:
Produce a full architecture plan *and working Python code* for this pipeline.

The code should include:

## 1. Directory layout
A recommended folder structure such as:

project/
  ├─ main.py
  ├─ core/
  │   ├─ search_engine.py
  │   ├─ crawler_engine.py
  │   └─ html_parser.py
  ├─ workers/
  │   └─ worker_runner.py
  ├─ utils/
  │   ├─ logger.py
  │   └─ file_utils.py
  ├─ output/

## 2. search_engine.py
A YouTube search implementation using **requests + HTML parsing**  
(no Selenium, no Playwright in this phase)

Must:
- return candidate video URLs reliably (scrolling via AJAX if possible)
- work without API keys

## 3. crawler_engine.py
Playwright-based implementation for:
- page navigation
- metadata extraction
- full comment + reply crawling (stable against hidden buttons & dynamic “more replies”)
- handle stalls, DOM reload issues

## 4. worker_runner.py
A minimal function that:
- receives a video URL
- runs Playwright async flow
- returns extracted comments count

## 5. main.py
The orchestrator that:
- receives a keyword
- fetches 50 candidate URLs
- filters them
- creates multiprocessing.Pool
- assigns each URL to workers
- aggregates results
- prints summary

## 6. Additional Requirements
- Code must support Windows/macOS/Linux
- Use spawn context for multiprocessing
- No global event loops (per-process loop only)
- Include robust logging
- Include detailed comments throughout
- Provide error-handling for each stage

## 7. Output format
Return the final answer as:

1) Project architecture explanation  
2) Full folder structure  
3) Python implementation for each module  
4) Instructions for running the system  

Generate code that can be run *as-is*.
