Issue 1: 데이터 무결성

created_time NULL 제약조건 위반 해결

문제 현상: NULL 제약조건 위반

  • 오류 발생: COMMENT_MASTER 테이블에 데이터를 저장하는 과정에서 오류 발생.
  • 원인: created_time 컬럼은 NOT NULL 제약조건이 설정되어 있으나, NULL 값이 전달됨.
  • 영향: 데이터베이스 저장 실패로 인한 크롤링 데이터 손실 및 시스템 불안정 야기.

해결 방안 1: 파싱 로직 강화 (Request Engine)

상대 시간 파싱 구현

YouTube의 "3일 전"과 같은 상대적 시간 표기를 절대 시간(datetime 객체)으로 변환하는 _parse_relative_time 함수를 신규 구현 및 적용했습니다.

기본값(Fallback) 적용

댓글 생성 시간 정보가 파싱되지 않거나 누락된 경우, 현재 수집 시간(collection_time)을 대체 값으로 사용하여 NULL 전달을 원천 차단했습니다.

해결 방안 2: 근본 원인 제거 (DB Manager)

  • 하드코딩 오류 발견: db_manager.py의 process_comments 함수 내부에서 created_time 컬럼에 강제로 None을 주입하는 코드를 식별했습니다.
  • 코드 수정: 하드코딩된 None 값을 제거하고, request_engine.py에서 전달받은 올바른 created_time 객체가 저장되도록 수정했습니다.
  • 최종 결과: 데이터베이스 저장 로직이 정상화되었으며, 무결성 오류가 완전히 해결되었습니다.

Issue 2: 메타데이터 정확도

동영상 like_count 수집 개선

문제 분석 및 개선 시도

  • 문제점: 일부 동영상의 like_count(좋아요 수)가 0으로 수집되거나 부정확함.
  • UI 구조 분석: YouTube 최신 ViewModel 구조를 분석하여 데이터 추출 경로(Path)를 재설정했습니다.
  • 리팩토링 시도: 초기 로딩 데이터와 API 응답 간의 시점 차이를 해결하기 위해 스크래핑 구조 변경을 시도했습니다.

현재 진행 상황 (Status)

  • 오류 수정 완료: 리팩토링 과정에서 발생했던 NameError 등 문법적 오류는 모두 수정되었습니다.
  • 실행 불안정: 코드 실행 흐름이 여전히 원활하지 않아 like_count가 완벽하게 수집되지 않는 상태입니다.
  • 향후 계획: 다음 작업 주기에서 최우선 과제로 선정하여 디버깅을 진행할 예정입니다.
